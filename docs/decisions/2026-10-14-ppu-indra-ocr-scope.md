Date: 2026-10-14

Context: Datalab Indra OCR (code Apache-2.0, weights modified OpenRAIL-M).
A license clearance email went to Datalab on 2026-10-14. Attachment A 2(c)
(competitor ban) is the open question. Nothing is released until they reply.

## Changed during the port

| Topic                            | Log said                              | Built                                                                                                    | Why                                                                                                     |
| -------------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Parity bar for the opencv engine | Exact text, IoU >= 0.98               | Kept, but line crops and deskewed pages are not byte-identical                                           | The reference cv2 resizes and warps through platform HALs (Carotene and KleidiCV on arm64, IPP on x86). |
| PDF render parity                | pdfium matches pypdfium2              | Text, order and markdown match; renders differ in anti-aliasing, glyph boxes by up to 0.57 pt            | The wasm is a different pdfium build than pypdfium2's 156.0.8076.                                       |
| Default engine on web            | opencv default                        | Node defaults to opencv; web and React Native default to canvas-native                                   | OpenCV.js is a multi-megabyte download a page should ask for; React Native has no OpenCV.               |
| WebGPU on web                    | Not decided                           | Not auto-picked (paddle picked it when available); opt in with `session.executionProviders`              | The Indra models are untested on the WebGPU provider.                                                   |
| Batch concurrency                | Paddle default 4 on CPU               | `convertBatch`, `convertStream` and serve default to 1                                                   | Each page allocates large tensors; more pages at once mostly add memory.                                |
| CLI commands                     | Paddle set (recognize, batch, stream) | `convert` (images and PDFs, md/text/json, `--out`), `detect`, `download-models`, `clear-cache`, `models` | Follows the Python `indra-ocr` CLI; one command covers single files and many.                           |
| Local test runs                  | `bun run test` with two workers       | `bun run test` is serial; `test:coverage` (CI) runs one worker until CI shows the peak                   | The two-worker run took 6.4 GB and froze an 8 GB Mac on 2026-10-14.                                     |
| ONNX Runtime sessions            | Library defaults                      | CPU memory arena off by default                                                                          | As the reference: with changing batch shapes the arena keeps every largest allocation.                  |
| Not ported                       | Everything                            | `table_heads` / `table_html_heads` and `balance_math`                                                    | The reference's `load()` never enables the first; the second has no caller.                             |
